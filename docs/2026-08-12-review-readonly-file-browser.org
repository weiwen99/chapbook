* Review 结论

评审对象： =docs/2026-08-12-design-readonly-file-browser.org= 第十轮修订版。
评审角色：Advisor；独立复核设计，不参与实现。

第十轮唯一实施前门槛已经关闭：

1. =encodedPath = element.dataset.nativePathEncoded= 是 row/panel 唯一保存的 action target。
2. 当前 tab、新 tab、预览、目录 fragment 下钻与下载全部把未 decode 的 encodedPath 交给
   =actionUrl=；模式参数只由 =URL.searchParams= 添加。
3. =decodeURIComponent= 只存在于 native-open Form seam；随后为一次
   =URLSearchParams= form encode、一次 Axum =Form= decode，handler 不再 percent-decode。
4. 新 fragment target 安装前先清空旧 panel state；缺失、格式非法或 decode 异常时 actions
   保持 disabled，不发送请求、不复用旧 target。

对完整设计做回归审查后，本轮未发现新的或回归的 P0/P1，也没有需要阻断实施的 P2。
终止条件“没有新的 P1”已经满足。建议 Design 状态恢复为“已批准（待实施）”，结束
本次 design 修正—review 闭环。

* 复审方法与证据

1. 对照 Design 的 =browser action path contract=、私有路由测试和 Chromium 验收矩阵，逐项追踪：

   #+begin_src text
   filesystem PathBuf
     -> server per-segment RFC 3986 encode
     -> ASCII-only data-native-path-encoded
     -> actionUrl(encodedPath)                  [URL actions: no decode]
     -> decodeURIComponent(encodedPath) once    [native-open only]
     -> URLSearchParams encode once
     -> Axum Form decode once
     -> resolve_within_root
     -> RecordingOpener exact PathBuf
   #+end_src

2. 验证以下 adversarial path classes：
   - CR / LF / CRLF：分别保持 =%0D= / =%0A= / =%0D%0A=；
   - 字面 =%0D=：保持 =%250D=，不与真实 CR sibling 碰撞；
   - 字面 =%2e%2e= / =%2F=：保持 =%252e%252e= / =%252F=，URL parser 不折叠
     dot segment，也不生成额外 path separator；
   - =?= / =#= / 反斜杠 / =+=：保持 encoded transport，不进入 query/fragment、不变成 slash，
     不发生 form =+= / space 混淆；
   - 非 ASCII、Unicode White_Space、Bidi_Control 与 Default_Ignorable：显示 codec 与 action
     identity 继续分离；
   - root：encodedPath 是合法空字符串而不是 attribute 缺失； =actionUrl= 生成 =/=，native-open
     form 的空 path 仍解析为 root；实现按 attribute presence 区分空值与缺失。
3. 验证 panel fail-closed：合法 target 后安装缺失/非法 replacement 或发生 native-open decode
   failure，旧 state 已清空，actions disabled，无请求。
4. 回归审查 =ResponseMode=、fragment/Org 安全、ServeFile origin isolation、anti-framing、搜索
   确定性与 permit 生命周期、opener 回收、RFC 8187、非 UTF-8 display-only 与私有 app/test seam；
   未发现新的或回归的 P0/P1。
5. 复核第九/十轮记录：两轮问题、设计更改和验证证据均保留在 Design 的
   “Advisor 闭环修订记录”，没有被最终状态更新覆盖。

* Findings

本轮无 P0、P1。没有新增实施前门槛。

* 已确认可实施的设计

1. =ResponseMode= 总序与目录/Markdown/Org/Office/code/media/unsupported 的完整 consumer。
2. fragment 单一安全出口、失败占位、Markdown/Org 危险内容过滤。
3. ServeFile =sandbox allow-scripts= opaque-origin 隔离与可信 UI anti-framing。
4. sorted BFS、directory-only identity、500/501 截断、 =Semaphore(1)= 与 blocking job 生命周期。
5. loopback + Host + Origin + token native-open 校验链。
6. Tokio Child async wait、kill-on-drop 与私有 =OpenWith= seam。
7. fallible app assembly、token reader 错误传播与 ConnectInfo plumbing。
8. exact =PathBuf= identity、非 UTF-8 display-only、安全 display codec 与全可见出口矩阵。
9. ASCII-only DOM path transport、encodedPath-only browser URL actions 与 native-open Form seam。
10. RFC 8187 filename、 =.cb-doc= / =.cb-doc-page= 双作用域 CSS、面包屑与渐进增强交互。

* 最终状态建议

- Design： =已批准（待实施）=。
- Review loop：结束；终止原因是第十一轮 Advisor 未发现新的或回归的 P0/P1。
- 实施阶段必须按 Design 的验收矩阵完成；不得把已关闭的 encoded/decoded/display identity
  三个 seam 合并回同一个字符串通道。

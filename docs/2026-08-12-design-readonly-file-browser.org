* 背景与需求

CB 当前是只读静态文件服务器，已具备高质量服务端文档渲染（.md/comrak、.org/orgize、
Office·CSV/anydoc、代码/syntect，全部纯 Rust 零运行时外部依赖）。向"基于浏览器的
Linux/macOS 本地文件浏览器"演进，核心壁垒是渲染质量而非文件列表本身。

目标用户场景：个人本机使用为主（xdg-open 打开本地文件是核心诉求之一），偶尔
=--host 0.0.0.0= 局域网分享浏览。

需求清单（用户选定）：

1. 文件名搜索（递归，服务端遍历，不建索引）。
2. 面包屑 + 键盘导航，接近原生文件管理器手感。
3. 侧边预览面板：点击文件不离开列表即可查看渲染内容。
4. 网格/缩略图视图（图片目录）。
5. 音视频浏览器内播放（Range 已支持，只需 viewer 页面/面板）。
6. 打开方式：当前 tab / 新 tab 两种入口。
7. 显式下载（Content-Disposition: attachment）。
8. 通过 xdg-open（Linux）/ open（macOS）用本机默认应用打开文件——仅本机场景。
9. 保持现有全部渲染能力与行为契约。

* 范围

** 目标

上节需求 1–9 全部。

** 非目标

- 任何写操作（上传/删除/重命名/移动/新建目录）——安全模型保持只读不变。
- 多根目录、文件系统漫游（保持启动时单一 canonicalized root）。
- 鉴权/多用户（只读 + 本机为主场景不需要；native-open 由 loopback+Host+Origin+token 保护）。
- 服务端缩略图生成（先用客户端 CSS 缩放 + lazy loading，性能不达标再另立提案）。
- 全文内容搜索、索引。
- SPA/前端框架（维持无构建步骤）。
- Unix 非 UTF-8 文件名的完整浏览器操作支持（raw-byte path codec + 非 String 路由）——本版采用
  “byte-escaped 显示、不可操作”的安全最小策略；如需完整支持另立设计。
- 归档文件（zip）内容列表、.ipynb 渲染等新文件类型管线（另立提案）。

* 方案选型

| 选项 | 收益 | 代价 |
|------+------+------|
| A. 渐进增强（选定） | 架构不变（maud 服务端渲染 + ~200 行 vanilla JS）；零新依赖；测试风格不变 | 交互流畅度略低于 SPA |
| B. vendored htmx | 自写 JS 更少 | 多一个前端依赖与概念层；交互点仅三四个，红利发挥不出 |
| C. SPA + JSON API | 体验上限最高 | 推翻"无前端构建步骤"决策；维护面翻倍；离线单二进制卖点受损 |

* 设计

** 响应模式 ResponseMode（统一解析，先于类型分派）[门槛 5]

所有 =/{*path}= 请求在文件类型 handler 之前集中解析响应意图，形成单一内部接口：

#+begin_src rust
enum ResponseMode {
    Download,  // 原始字节 + Content-Disposition: attachment
    Raw,       // 原始字节 (ServeFile)
    Fragment,  // 安全 HTML fragment (预览面板)
    Full,      // 完整页面 (渲染或协商)
}
#+end_src

解析规则（在 =serve_path= 内、目录/文件分派之前执行一次）：

1. =download= 存在 → Download（最高优先，绕过所有渲染器）。
2. 否则 =raw= 存在 → Raw。
3. 否则 =fragment= 存在 → Fragment。
4. 否则 =view= 存在 → Full（强制渲染，既有语义）。
5. 否则按既有行为：.md/.org → Full；Office/代码按 Accept 协商（含 text/html → Full，
   否则 → Raw）；其他文件 → Raw。

优先级 =download > raw > fragment > view= 为总序，多参数同现时按此裁定，测试锁定。

契约：

- Download 一律走 ServeFile 原始字节 + attachment header；.md/.org/Office/代码无一例外；
  Range 与条件请求能力由 ServeFile 保留。
- Raw 走既有 =serve_file= 管线（含 text/* charset 修补）。.md/.org 因此新增 =?raw=1=
  原文支持（此前 =raw= 被忽略仍渲染 HTML，属新增行为，测试锁定）。
- 所有 ServeFile 响应统一附加 raw-content sandbox；Download 响应虽由 attachment 阻止内联，
  仍保留同一 header，避免形成第二个出口。详见“主动内容与可信 UI 的 origin isolation”。
- Fragment 见下节"严格接口"；不受 fetch 默认 =Accept: */*= 影响（模式已显式选定）。
- 目录：Fragment → 迷你列表片段；Download/Raw/View 对目录无意义，忽略并返回完整目录页。
- 判定顺序不变：目录 → .md → .org → Office/CSV → 代码 → ServeFile。

** 路由与端点（routes.rs）

- =GET /__/search?q=<query>= — 从 root 递归文件名搜索，渲染结果页（详见"递归搜索"）。
- =POST /__/native-open= — form 字段 =path= + =token=；校验链见"本机打开与安全"。
- 现有 =/{*path}= 增三个查询参数：=download= / =fragment=（语义见 ResponseMode）与既有的
  =raw= / =view=。
- 图片/音视频：Full/Raw/Download 走 ServeFile 原生（浏览器自带查看器/播放器，Range 已有）；
  Fragment 返回 =<img>/<video>/<audio>= 包装片段。
  扩展名集合：图片 =png jpg jpeg gif webp svg avif ico=；视频 =mp4 webm mov m4v=；
  音频 =mp3 flac ogg opus wav m4a=。
- 非法 sort 返回 404 等既有行为契约不变。
- ConnectInfo plumbing：=main.rs= 改为
  =axum::serve(listener, app.into_make_service_with_connect_info::<SocketAddr>())= [门槛 1]。

** fragment：严格接口（安全契约）[门槛 2]

fragment 是预览面板的唯一内容来源，必须是严格接口——**任何路径都不得返回裸内容**：

- 集中出口：单一 helper（=serve_fragment(path, kind, metadata)=）处理全部类型，
  四个文件类型 handler 不各自形成 fallback 语义。kind 由类型分派确定：
  Dir / Markdown / Org / Office(Format) / Code(lang) / Media / Unsupported。
- 成功响应：CB 生成的安全 HTML fragment，统一为 =<div class="cb-doc">…</div>=
  （文档/代码）或媒体/迷你列表包装；Content-Type =text/html; charset=utf-8= +
  =X-Content-Type-Options: nosniff=。不含 =<!DOCTYPE>=/=<head>=/页面级样式（宿主已带
  .cb-doc 样式，见"渲染管线扩展"）。
- 失败响应（非 UTF-8、超限、anydoc 转换失败、不支持的类型）：统一返回占位 fragment
  =<div class="cb-doc"><p class="cb-no-preview">无法预览：<原因></p></div>=（200，
  maud 转义文案，**不含原始文件字节**）。fragment 模式禁止回退到 ServeFile 或
  text/plain 原文。
- 渲染安全性由各生成管线明确保证：
  - Markdown raw HTML 与危险 URL 继续由 Comrak 默认的 =unsafe=false= 处理。
  - Org 的 =OrgHtmlHandler= 必须显式覆盖三类元素，Full 与 Fragment 复用同一
    =org::render=，不得在 fragment 出口另做字符串清洗：
    1. HTML =ExportBlock=：对 =contents= 使用 =HtmlEscape= 输出文本；
    2. HTML =Snippet=：对 =value= 使用 =HtmlEscape= 输出文本；
    3. =Element::Link=：先执行私有 =dangerous_org_url=，再分别以 =HtmlEscape=
       输出 href 与 label。危险 URL 保留 anchor/label 但输出 =href=""=，与 Comrak 行为一致。
  - =dangerous_org_url= 采用 Comrak denylist 语义并对浏览器 URL 规范化旁路做加固：
    截取首个 =:= 前的 scheme candidate，移除其中 ASCII whitespace/control、转为 ASCII
    lowercase；命中 =javascript= / =vbscript= / =data= / =file= 即危险。无冒号的相对
    URL、=#fragment=、以及 =http/https/mailto= 保留；未知但未命中 denylist 的 scheme
    维持 Comrak 兼容行为。Org link 的 =data:= 一律拒绝，不复用 Comrak 对部分
    =data:image/*= 的图片例外，因为此处是导航链接而非图片渲染。
  - 代码经 syntect 转义；媒体以 =<img>= 嵌入（SVG 脚本在 img 上下文不执行，不做 inline）。
- 前端职责：=fetch= 后检查 =response.ok= 且 Content-Type 含 =text/html= 才注入
  =innerHTML=；否则用 =textContent= 显示错误，不得注入。

验收锁定：超限代码、非 UTF-8 Markdown、Office 转换失败的 fragment 均不含原始字节；
hostile Markdown、Org ExportBlock/Snippet 和危险 Org link 在 Full/Fragment 下都不生成活动
内容；正常 md/org/Office/代码 fragment 不含 =<!DOCTYPE>=/=<head>=/=<style>=。

** 主动内容与可信 UI 的 origin isolation [第二轮门槛 1]

选择 **CSP sandbox**，不增加第二 listener/port/origin。分离 origin 能保留原始 HTML 的
同源 XHR，但会给单端口、局域网地址、链接生成和 CLI 增加第二套寻址规则；对本机只读浏览器过重。

- =serve_file= 是唯一 raw-content 出口；它对 **每个** ServeFile 响应附加：
  =Content-Security-Policy: sandbox allow-scripts=。唯一例外是 Chromium 在
  document sandbox 下拒绝加载音视频（浏览器验收矩阵已预设该调整路径，见下）：
  非 download 的 200/206 =audio/*=、=video/*= 响应省略 sandbox，并强制
  =X-Content-Type-Options: nosniff=。例外**只按媒体类型**区分，绝不因扩展名/MIME
  泛化为 allowlist 出口，且一律不含 =allow-same-origin=。
- CSP **不得**包含 =allow-same-origin=。顶层 HTML、SVG、XML 等主动文档因此获得 opaque
  origin；浏览器发送的 Origin 为 =null=，不能读取目录页、搜索页或 token，也不能通过
  native-open 的 Origin 精确匹配。
- 保留 =allow-scripts= 是兼容性取舍：原始 HTML 的脚本仍可执行，但 fetch/XHR、storage 与
  同源 DOM 访问失效；forms/popups/downloads 等能力因未加入对应 sandbox token 而保持禁用。
  当前“HTML 交给浏览器渲染”的行为保留，但不承诺本地 Web 应用的同源 API 能力。
- CB 生成的目录页、搜索页、完整文档页、fragment 与静态资源不经过 ServeFile，不加 sandbox；
  它们是可信 UI origin。媒体作为 =img/video/audio= 子资源时不执行文档脚本，Range 不受影响。
- =download= 仍附加 attachment；sandbox header 对下载无行为影响。

验收：ServeFile 返回的 =evil.html= 与顶层 =evil.svg= 响应都带
=sandbox allow-scripts= 且不含 =allow-same-origin=；浏览器中二者的 =fetch("/")=
不可读 token-bearing 页面，从其发出的 native-open 请求因 =Origin: null= 返回 403；
可信目录 UI 的正向请求仍返回 204。

** token-bearing UI anti-framing [第三轮门槛 2]

Origin 校验只证明 native-open 请求由可信页面发出，不能证明可信页面未被 clickjack。
目录页与搜索页因此通过统一 =trusted_ui_response(markup)= 出口添加：

- =Content-Security-Policy: frame-ancestors 'none'=
- =X-Frame-Options: DENY=（仅作旧浏览器兼容，主防线是 CSP）

=frame-ancestors= 必须是 HTTP response header，不能放进 =<meta>=。目录页与搜索页无论当前
peer/Host 是否满足 token 嵌入条件都带相同 header，避免安全行为随入口分叉。fragment 与静态
资源不是 frameable token-bearing document，不单独添加。该策略与 ServeFile 的
=sandbox allow-scripts= 分属可信 UI / raw content 两条出口，不合并 header，也不互相替代。

验收：目录页与搜索页响应均带两项 anti-framing header；跨 origin iframe 无法呈现页面，
合成点击不能触发 native-open；可信顶层目录页的正向路径仍返回 204。

** 递归搜索 [门槛 3]

- =GET /__/search?q=<query>=：大小写不敏感子串匹配文件名（目录也参与匹配），
  从 root 递归，上限 500 条，截断时页面提示，空 q/纯空白 q 直接返回提示页不遍历。
- 进程级并发门：=AppState= 持有 =Arc<Semaphore>=，容量固定为 1。非空查询通过私有
  =run_blocking_search= 获取 permit；忙时立即返回 429 + =Retry-After: 1=，不排队第二次扫描。
  permit 移入 =spawn_blocking= closure，直到真实遍历结束才释放；客户端断开或 handler
  future 被取消不会释放 permit，也不会取消已经启动的 blocking task。
- 私有并发/生命周期 seam [第四轮门槛 2]：

  #+begin_src rust
  enum BlockingSearchError {
      Busy,
      Task(tokio::task::JoinError),
  }

  async fn run_blocking_search<T, F>(
      gate: Arc<Semaphore>,
      job: F,
  ) -> Result<T, BlockingSearchError>
  where
      T: Send + 'static,
      F: FnOnce() -> T + Send + 'static;
  #+end_src

  helper 内先 =try_acquire_owned=；Busy 时不调用 job。成功后把 owned permit 与 job
  一起移入 =spawn_blocking=，await JoinHandle 并显式映射 JoinError。HTTP handler
  仅传入 =move || listing::search(...)=，将 Busy 映射为 429、Task 映射为 500 + warn。
  helper/error 全部 private，不给 =AppState= 增加 test runner 或第二套 adapter。
- 实现（=listing.rs= 新增 =search= 阻塞函数；handler 仅负责参数、helper 调用与 HTTP 映射）：
  - 迭代式 BFS 队列（=VecDeque<PathBuf>=，seed 为 root），不用递归，避免深目录爆栈。
  - 在处理每个目录前先收集全部 =DirEntry=，按 Unix 原始文件名 bytes
    （=OsStrExt::as_bytes()=）升序排序，再进行匹配与入队。全局顺序定义为：
    深度升序；同一深度按父目录既有 BFS 顺序；同一目录按上述 bytes 顺序。
  - root identity 预先加入 =visited_dirs=。每个成功读取 metadata 的目录项都先独立执行
    名称匹配并可进入结果；普通文件从不加入 identity set，因此 hard link 的每个名称/路径
    都保留。
  - 若匹配后的条目是目录，再以跟随符号链接所得 =(dev, ino)= 检查 =visited_dirs=；
    仅首次 identity 入队遍历子树，后续 alias 自身仍可作为匹配结果，但不再次下钻。
    因此 alias 子树选择规则为“最浅层优先，同层 bytewise 路径优先”，=loop -> .=、
    =parent -> ..= 与多别名均终止且可复现。
  - 目录项/metadata 失败逐项跳过；子目录 =read_dir= 失败跳过该子树（debug 日志），
    不使整个搜索 500。
  - 查询字符串在 handler 内 =to_lowercase()= 一次；候选项逐个
    =display_name.to_lowercase().contains(q)=。非 UTF-8 名称因此可用 escaped label 搜索。
  - 结果直接使用确定性遍历顺序，不做“截断后再排序”。遇到第 501 个 match 立即停止，
    返回前 500 项 + truncated。确定性保证以扫描期间文件树未变化为前提。
- =spawn_blocking= 扫描启动后不可 abort；Ctrl-C 可能等待当前一次有限遍历结束。这是同步
  文件系统 API 的已知边界，并发门确保最多只有一次扫描占用 blocking pool。
- 结果页：页头搜索框（q 预填）+ 面包屑（root / 搜索："q"）+ 复用 striped 表格，
  列：名称（可操作 UTF-8 路径为链接，非 UTF-8 路径为 display-only span）、位置
  （可操作时父目录为链接，否则按 segment byte-escaped 显示）、大小、修改时间。
  行尾操作只对 actionable row 渲染；结果页同样支持键盘导航与预览面板。

** 面包屑与交互契约 [门槛 8]

*** 面包屑（目录页与搜索页）

- 结构：=nav.cb-breadcrumb=，=根目录名 / seg1 / seg2 / … / 当前目录=。
- 根节点：标签为 root 目录名（basename），href 为 =/=。
- 中间节点：href 为逐级累计路径，每段用 =PATH_SEGMENT_ENCODE_SET= 编码
  （与 =FileMeta::href= 同一编码器，空格 =%20=，中文/+/=/# 均安全）。
- 当前节点：纯文本不生成链接。
- 搜索页面包屑：root 链接 + "搜索"当前节点；行内父目录链接见上节。
- 特殊字符目录名的逐级跳转由测试锁定。

*** 鼠标与键盘操作总表（无歧义）

| 操作 | 行为 |
|------+------|
| 单击文件名链接 | 当前 tab 打开（无 JS 时的原生行为，保持可用） |
| Ctrl/⌘+单击、中键 | 新 tab（浏览器原生 anchor 行为） |
| 单击行非链接区域 | 选中该行 |
| 双击行 | 当前 tab 打开 |
| 行尾 =预览= 图标 | 预览面板打开该文件 |
| 行尾 =↗= 图标 | 新 tab（=target=_blank rel=noopener=） |
| 行尾 =⤓= 图标 | 下载（=?download=1=） |
| =j/k/↑/↓= | 移动选中行（到边界停，不循环） |
| =Enter= | 当前 tab 打开选中行 |
| =o= | 新 tab 打开选中行 |
| =p= | 预览选中行/切换预览面板 |
| =v= | 切换列表/网格视图 |
| =Backspace= | 上级目录 |
| =/= | 聚焦搜索框 |
| =Esc= | 关闭预览；搜索框聚焦时先失焦 |

- 快捷键守卫：事件 target 为 =input/textarea/select/[contenteditable]= 或带
  Ctrl/Meta/Alt 修饰键时一律忽略（搜索框内可正常输入 o、p、/ 并按 Backspace）。
- 被替代的浏览器默认行为显式 =preventDefault=（=/=、Backspace、Enter、o、p、v）。

- 非 UTF-8 display-only 行仍可被鼠标/键盘选中以读取元信息，但没有 anchor、action URL 或
  =data-native-path-encoded=；双击、Enter、=o/p= 和所有行尾动作对该行均为 no-op。
  列表/网格均显示“非 UTF-8 名称（仅显示）”提示，不能误以为操作已执行。

- 所有 filename/path segment 的可见容器统一由 =display_segment(os_str)= 生成
  =<bdi dir="auto">安全 label</bdi>=；选择/键盘状态只读 exact Path identity，
  不从 textContent 或 accessible label 反推 action。

** 前端（新增 assets/chapbook-browser.js，vanilla，无构建步骤）

- 预览面板：目录页/搜索页静态骨架右侧固定面板（≈40rem）。所有行与 fragment wrapper
  只携带 ASCII-only =encodedPath=；预览 URL 由统一前端 helper 基于 encodedPath 构造，
  返回后按 fragment 契约注入。面板工具栏：当前 tab 打开 / 新 tab 打开 / 下载 /
  本机打开（仅当页面嵌入了 token，见下节）。
- 面板内目录迷你列表的条目链接由 JS 拦截为面板内下钻；下钻同样保存 encodedPath，
  不保存 decoded URL target。工具栏“当前 tab 打开”用于离开面板进入完整页。
- 视图切换：列表/网格 toggle，localStorage 持久化；网格项图片用
  =<img loading="lazy" decoding="async">= 客户端缩放（零新依赖），非图片显示扩展名标签。
- 页头常驻搜索框，普通 form GET 提交到 =/__/search=（无 JS 可用）。
- 渐进增强：无 JS 时文件名链接、搜索、面包屑、排序、下载均可用；JS 只叠加
  键盘/面板/视图切换/行尾图标行为。

** 本机打开与安全（关键）[门槛 1、6]

*** token 生成与嵌入

- 启动时从 =/dev/urandom= 读 16 字节生成 token（hex 32 字符，零新 crate）；
  读取失败直接启动失败并报错（不降级为弱安全运行）。
- 嵌入条件（二者同时满足，仅目录页/搜索页）：
  1. =Result<ConnectInfo<SocketAddr>, _>= 提取成功且 peer 为 loopback（提取失败按
     非 loopback 处理，fail closed）；
  2. 请求 =Host= 为字面 loopback 主机：=localhost=（大小写不敏感）/ =127.0.0.1= /
     =[::1]=，允许附带任意端口；其余一律不嵌入。
- 嵌入形式：=head= 内 =<meta name="cb-native-open-token" content="…">= +
  行尾/面板"本机打开"按钮（无 token 时按钮不渲染，局域网客户端看不到入口）。
- 这同时是 DNS rebinding 防线：rebinding 后 peer 是 loopback 但 =Host= 仍是恶意域名，
  页面拿不到 token，POST 也在 Host 校验处被拒。不把 SOP / Private Network Access
  当作防线。

*** POST /__/native-open 校验链（任一失败即拒，顺序固定）

1. peer 为 loopback，否则 403——提取形式为 =Result<ConnectInfo<SocketAddr>, _>=
   （axum 对任意 =FromRequestParts= 提取器提供 =Result= 形式；=ConnectInfo= 本身
   无 =OptionalFromRequestParts= 实现，=Option<ConnectInfo>= 不可用），Err 即 403；
2. =Host= 为字面 loopback 主机（规则同上），否则 403；
3. =Origin= 必须存在且等于 ="http://" + Host=（两者 lowercase 后比较；CB 无 TLS），
   否则 403——同源页面 fetch POST 必带 Origin，跨域表单/脚本同样带 Origin 但域名不匹配；
4. form =token= 与启动 token 相等，否则 403；
5. form =path= 经 =resolve_within_root= 解析（复用现有不变量），越界 403；
6. 目标存在（文件或目录），否则 404；
7. =opener.open(resolved)=，见下。

- 日志：失败路径记 warn（原因 + path），**token 与请求提供的错误 token 均不得写入日志**。
- 成功响应 204；前端按钮短暂反馈。
- 风险注记：macOS =open= 对 =.command= 文件是直接执行——上述整条链不可省。

*** 浏览器路径身份与 Unix 非 UTF-8 filename [第四轮门槛 1]

选择安全最小策略：非 UTF-8 路径 **仅显示、不可通过浏览器操作**。本版不引入 raw-byte
path codec，也不把 lossy Unicode 当作 identity。

- =FileMeta= 明确拆分：
  - =relative_to_root: PathBuf=：唯一文件系统 identity，始终保留原始 OsStr bytes；
  - =display_name: String=：仅用于显示/搜索文本，绝不反推 Path；
  - =browser_path(&self) -> Option<&str>=：仅调用整个 =relative_to_root.to_str()=；
  - =browser_path_encoded(&self) -> Option<String>=：仅在 browser_path 为 Some 时逐 segment
    做 RFC 3986 percent-encoding，返回无前导斜杠的 ASCII-only DOM transport；
  - =href(&self) -> Option<String>=：在同一 encoded 值前加 =/=，不实现第二套 path codec。
  href/DOM transport/native path/download filename 均禁止 =to_string_lossy=。
- 私有 =escape_os_name= 是 identity 之外的统一安全显示编码 [第五至八轮门槛]。
  =Default_Ignorable_Code_Point= matcher 固定为 **Unicode 17.0.0**；升级必须按对应
  =DerivedCoreProperties.txt= 更新 matcher、总数和边界测试，不跟随 Rust toolchain 隐式漂移。
  =White_Space= 直接使用 =char::is_whitespace()=，不增加第二张生产 range table 或运行时依赖；
  Unicode 17.0 的 25 项固定测试向量锁定当前显示契约。
- 私有 =is_default_ignorable(char) -> bool= 以静态 =matches!=/range table 覆盖
  Unicode 17.0.0 的全部 4,174 个 =Default_Ignorable_Code_Point=。按 UCD 的 27 个源范围
  固定为：

  #+begin_src text
  00AD; 034F; 061C; 115F..1160; 17B4..17B5; 180B..180D; 180E; 180F;
  200B..200F; 202A..202E; 2060..2064; 2065; 2066..206F; 3164;
  FE00..FE0F; FEFF; FFA0; FFF0..FFF8; 1BCA0..1BCA3; 1D173..1D17A;
  E0000; E0001; E0002..E001F; E0020..E007F; E0080..E00FF;
  E0100..E01EF; E01F0..E0FFF
  #+end_src

  =Bidi_Control= 是该 matcher 的安全关键子集，不维护第二份生产 matcher；独立 12 项测试保留。
- Unix 实现按原始 byte stream 分段解码 UTF-8，并仅对 =U+0020 SPACE= run 做
  segment-aware 预扫描：
  - 恰好一个且不位于 segment 首尾的 =U+0020= 原样保留（如 =My File.txt=）；
  - segment 首/尾或长度 ≥2 的 U+0020 run 中，每个 byte 都输出大写 =\\x20=。
  其余每个输入 byte/scalar 只进入以下一个分支，顺序固定：
  1. 非法 UTF-8 byte → 大写 =\\xNN=；
  2. 字面反斜杠 → =\\=；
  3. 除 U+0020 外的 =char::is_whitespace()= → 大写 =\\u{NNNN}=；
  4. 其余 ASCII control/DEL → 大写 =\\xNN=；
  5. 其余 =char::is_control()= scalar → 大写 =\\u{NNNN}=；
  6. =is_default_ignorable(c)= → 大写 =\\u{NNNN}=，不得原样进入 DOM；
  7. 其余合法 UTF-8 scalar 原样保留。
  whitespace 分支位于 control 与普通 scalar 分支之前，因此 U+0009–U+000D、U+0085 及
  18 个非 ASCII、非 Cc =White_Space= 都统一输出 =\\u{NNNN}=。
  Unicode escape 使用大写 hex、至少 4 位。escape introducer 反斜杠自身先被转义，因此：
  - 原始 byte =0xFF= → =\\xFF=；合法 =U+FFFD= → =�=；字面 =\\xFF= → =\\\\xFF=；
  - 原始 =U+00A0= → =\\u{00A0}=；字面 =\\u{00A0}= → =\\\\u{00A0}=；
  - 原始 =U+200B= → =\\u{200B}=；字面 =\\u{200B}= → =\\\\u{200B}=；
  - 原始 =U+202E= → =\\u{202E}=；字面 =\\u{202E}= → =\\\\u{202E}=；
  - 尾随 U+0020 → =\\x20=；字面 =\\x20= → =\\\\x20=。
  这些 label 均不碰撞。maud 在最后一步负责 HTML text/attribute escaping。
- 私有 =display_segment(&OsStr) -> Markup= 只做一件事：
  =<bdi dir="auto">{escape_os_name(name)}</bdi>=。每个 segment 单独 isolate，路径分隔符、
  metadata 列、扩展名 badge 与行尾图标位于 =bdi= 外；不用固定 =dir="ltr"=，保留正常
  Arabic/Hebrew filename 的自然方向，同时限制跨 segment 的 bidi 影响。
- 用户可见 filename/path 出口必须穷举并统一：
  - 可承载 markup：目录表格、网格、搜索名称/location、面包屑、=Index of …= heading、
    目录 fragment、预览标题/工具栏，逐 segment 使用 =display_segment=，分隔符在 =bdi= 外。
  - 纯文本/attribute：目录完整页 =<title>=、tooltip、=title=/=aria-label= accessible name，
    以及 Markdown/Org/Office/code 完整页未提供文档 title 时的 filename fallback，
    使用 =escape_os_name=（多 segment 路径逐段 join）。
  - Markdown front matter title / Org =#+TITLE= 属于文档内容而非 path identity，不替换为
    OS-name helper；仅缺失 metadata 时的 filename fallback 走 helper。
  任何 renderer/JS 禁止把 raw basename、=Path::display()= 或 =to_string_lossy= 写入
  用户可见文本。私有 =display_path_text= / =display_path_markup= 集中完成逐 segment join，
  不允许各页面自行拼接。
- 非 UTF-8 名称仍按 escaped =display_name= 参与列表排序与大小写不敏感搜索；命中结果同样
  display-only。root 本身由 =/= 表示，root basename 若非 UTF-8 以同一规则生成 breadcrumb
  label，不影响其 UTF-8 子路径的 actionability。
- browser actionability 以 **整个 root-relative Path 的 =to_str()=** 为准，不只检查 basename。
  任一祖先 segment 非 UTF-8 时，该行在目录页、搜索结果和网格中都：
  - 以 =<span>= 显示 escaped label，不渲染文件名 anchor；
  - 不渲染当前 tab、新 tab、预览、下载、native-open 控制；
  - 不输出 href、=data-native-path-encoded= 或其他可被 JS 当作 action identity 的值；
  - 若它是目录，也不能从浏览器进入。UTF-8 名称的 symlink 即使目标真实路径含非 UTF-8，
    仍以 symlink 自身的精确 UTF-8 relative path 操作，不受此限制。
- Axum =Path<String>= 因而只承载可逆 UTF-8 browser paths；完整 raw-byte URL codec 与
  =OsStringExt::from_vec= 路由明确不属于本版。

验收：同目录中的非 UTF-8、字面 escape、Bidi_Control、Default_Ignorable、Unicode
=White_Space= 与异常 U+0020 fixtures 都显示为互不相同的安全 label。重点包含
=U+00A0=、=U+1680=、=U+2000-U+200A=、=U+2028=、=U+2029=、=U+202F=、=U+205F=、
=U+3000= 及它们的字面 =\\u{...}= 对照，也保留既有 default-ignorable 对照。
非 UTF-8 行完全无 action identity/controls；含上述合法 UTF-8 scalar 的行仍可操作，
但所有可见出口只显示统一 codec 结果。任何 RecordingOpener 断言比较完整 =PathBuf=，
禁止以显示 label 或 =to_string_lossy= 比较。

*** browser action path contract [第二轮门槛 4，第四轮收紧，第九/十轮 transport 修正]

- 本契约只适用于 =browser_path() == Some= 的 UTF-8 行。服务器最终接收的 filesystem value 是
  **无前导斜杠的、root-relative decoded exact UTF-8 path**；root 自身为空字符串。
  它源于 =relative_to_root.to_str()=，绝不源于 display label、href 或浏览器 URL。
- decoded path **禁止直接写入 HTML attribute**。单一 server helper 调用
  =browser_path_encoded()=，生成 =data-native-path-encoded=：逐 segment 使用既有
  =PATH_SEGMENT_ENCODE_SET=，segment 间保留 =/=，无前导斜杠。结果只含 ASCII；
  U+000D/U+000A 不受 HTML input-stream newline normalization 影响。
- =encodedPath = element.dataset.nativePathEncoded= 是 JS 唯一保存的 row/panel action target。
  目录表格、搜索结果、网格项和 fragment wrapper 全部调用同一 server helper；attribute
  缺失时禁用全部 action。禁止从 label、导航 href、=location.pathname= 或 DOM 可见文本
  反推 identity。
- 当前 tab、新 tab、预览、目录 fragment 下钻与下载 **不得 decode encodedPath**。
  单一 =actionUrl(encodedPath, mode)= 构造 =new URL("/" + encodedPath, location.origin)=，
  再仅通过 =url.searchParams.set("fragment", "1")= /
  =url.searchParams.set("download", "1")= 增加模式；Full 不加参数。不得把 decoded string
  传给 =URL=/=fetch=/=location=/=window.open=，也不得用字符串拼接追加 query。
- 只有 native-open Form 路径调用 =decodeURIComponent(encodedPath)= 一次，随后交给
  =URLSearchParams= 执行一次 =application/x-www-form-urlencoded= 编码。Axum =Form=
  执行一次 form decode，所得 path 直接交给 =resolve_within_root=；handler 不再
  percent-decode。
- 字面 =%= 先由 server 编成 =%25=；例如 basename 字面 =%2e%2e= 的 attribute 是
  =%252e%252e=。URL actions 直接使用该 encoded 值；native-open 一次 decode 后仍为字面
  =%2e%2e=，经 Form round-trip 后始终是 =Component::Normal=，不会变成 =ParentDir=。
- 切换/下钻 fragment 时必须先清空 panel action state，再从新响应 wrapper 安装 encodedPath。
  attribute 缺失、格式非法或 native-open decode 异常时保持 actions disabled，显示操作失败；
  不发送请求，不复用旧 target。
- clean cutover：删除 decoded =data-native-path=、任何 decoded URL target 与散落的 URL
  构造；不保留双格式或 decode-then-URL 兼容路径。

*** 子进程回收与 opener seam [第二轮门槛 3、5]

- =AppState= 持有随机 token 与私有 =Arc<dyn OpenWith>=；trait 不导出：

#+begin_src rust
trait OpenWith: Send + Sync {
    /// spawn 成功即返回 Ok; Child 由实现异步回收. 仅 spawn 失败返回 Err.
    fn open(&self, path: &Path) -> std::io::Result<()>;
}
#+end_src

- 生产 adapter =PlatformOpener= 使用 =tokio::process::Command=：=xdg-open <path>=
  （Linux）/ =open <path>=（macOS），stdin/stdout/stderr 全 null，
  =kill_on_drop(true)=。
- =spawn()= 成功后立即把 =Child= 移入普通 =tokio::spawn= task 并 =wait().await=；
  handler 随即返回 204，不等待 opener 完成。正常退出会被异步 reap；wait 失败只记 warn。
  runtime shutdown 可取消 wait task，不会等待不可取消的 blocking closure；若 opener
  仍挂起，Child drop 触发 kill-on-drop，保证 Ctrl-C 不被它阻塞。
- 私有 =spawn_reaper(child) -> JoinHandle<()>= 封装 wait task，生产 adapter 丢弃 handle，
  私有单元测试可 await/观察其生命周期。
- =open()= spawn 失败 → 500 + warn；opener 收到的必须是 =resolve_within_root= 后的绝对路径。

*** App 构造与私有测试装配 [第二轮门槛 5]

- 生产接口改为 =pub fn app(root: PathBuf) -> io::Result<Router>=。内部

- Router 的真实装配为私有
  =fn app_with(root, token, opener: Arc<dyn OpenWith>) -> Router=；它同时创建搜索

** Content-Disposition 与 RFC 8187 [门槛 7]

- =meta.rs= 新增独立编码器 =ATTR_CHAR_ENCODE_SET=：RFC 8187 §3.2.1 =attr-char=
  之外的字符全部 percent-encode（非 ASCII 字节恒编码）。**不复用**
  =PATH_SEGMENT_ENCODE_SET=——它面向 RFC 3986 path segment，会保留 =(= 、=)= 、=*=，
  而 =attr-char= 不含这些字符。
- header 形如：
  =Content-Disposition: attachment; filename="<ascii-fallback>"; filename*=UTF-8''<encoded>=
  - 只编码文件 **basename**，不把目录路径写入 filename。
  - ascii-fallback：basename 中 =[A-Za-z0-9._-]= 之外替换为 =_=，并转义反斜杠与双引号。
- 示例：=报告 (final)*.md= → =filename*=UTF-8''%E6%8A%A5%E5%91%8A%20%28final%29%2A.md=。
- 文档术语统一为 RFC 8187（已取代 RFC 5987）。
- header 在 Download 模式下由 =serve_file= 出口统一附加（单点）。

- =--host= 默认值 =0.0.0.0= → =127.0.0.1=（本机为主）；偶尔局域网时显式

** 错误处理

- 搜索：坏目录项/失败子树逐个跳过；501 项截断并提示；空结果显示提示页；空 q 不遍历；
  gate 忙时返回 429 + =Retry-After: 1=。已开始扫描不可取消，owned permit 由

- fragment：全部失败路径返回占位片段（200），永不返回裸内容；Org HTML export/snippet

- ServeFile：所有响应统一附加 =CSP: sandbox allow-scripts=，不得加入

*** 公共路由集成测试（tests/router.rs）

*** 私有路由单元测试（src/routes.rs）

- search gate helper 使用私有可控 job，不依赖 tempdir 规模、sleep 或调度竞速：
  1. 预先占有 gate，传入设置 AtomicBool 的 job；断言返回 Busy 且 job 未调用；
  2. 首个 job 通过 channel 发出“closure 已启动”，随后阻塞等待 release；
  3. release 前第二次 helper 调用稳定返回 Busy；HTTP 映射测试另断言 429 +

  5. panic job 映射为私有 =BlockingSearchError::Task=，HTTP 层返回 500，不泄漏 permit。

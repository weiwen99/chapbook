# 03: 统一顶部图标工具区与渐进增强 HTML

**What to build:** 目录、搜索、树与独立阅读页共用一套工具区 markup 和主题样式，包含互斥视图图标、隐藏项开关及排序入口。

**Blocked by:** None（[01](01-shared-listing-policy.md) 已完成）。

**Status:** ready-for-agent

## Context

产品决定见 [spec.md](../spec.md) Q1–Q7、Q14–Q16、Q20、Q25。目录预览跟随主工具区，不重复工具栏。客户端状态与事件归 [04](04-shared-browser-state-and-navigation.md)。

## Required change

- 在 `src/render.rs` 为 page_shell 与 doc_page 复用一个工具区渲染 helper；消费 02 提供的目录/搜索/独立阅读语义、规范编码位置、q 与 ListingOptions，并一致输出给 04。编码 identity 复用 `data-native-path-encoded`，不凭 DOM 缺少 table、显示标题或 displayed path 猜测页面类型/目标。
- 页面顶部正常流布局：左搜索；右树/列表/网格图标组、隐藏项开关、排序入口。树壳不能把它隐藏或搬进左侧树栏；树自身的折叠/抽屉控制仍是独立导航动作。
- 图标用自包含 SVG 与继承主题颜色，不引入外部图标字体、CDN 或构建工具。复用现有颜色变量和 focus-visible 轮廓，hover 与键盘焦点均能看到含义，控件具有可访问名称、明确选中/禁用状态；不写 inline 事件 handler。
- 窄屏允许搜索与控件组换行，但三个视图图标始终成组；保持树抽屉、正文/TOC、长代码与媒体的既有窄屏行为，不新增固定悬浮工具栏。
- 独立阅读页不算第四种视图，三个图标都不显示选中态；隐藏/排序禁用并说明作用范围。返回列表/网格导航到父目录，树入口保留当前文档作为打开条目。
- 排序入口提供六键/两方向。类型列显示安全转义扩展名。已有表头排序快捷操作与箭头沿用，但进入同一个显示规则更新流程并保留 hidden/q，不能形成第二份状态。
- 无 JS 时列表的隐藏和排序可单次链接/表单操作使用；不要让无 JS 用户依赖 onchange 脚本，也不要要求 JS 用户额外点应用。树/网格入口按真实能力渐进增强，不伪造无 JS 树视图。
- 搜索 form 与目录导航传递有效 sort/hidden；GET 表单用实际提交字段保留规则，不只把参数放在 action query。重新搜索保留 sort/hidden；条目、../、面包屑与搜索位置导航保留规则，实际离开搜索才移除 q。保留唯一可见面包屑、辅助技术 h1、thead 与非根目录 ../ 行契约。
- 公共工具区样式放在目录/搜索/独立阅读页都可用的现有资源中；不复制一套略有差异的图标组或 tooltip 样式。

## Acceptance criteria

- [x] 三种视图始终只有同一组顶部入口，选中态互斥；独立阅读页无浏览视图选中态。
- [x] 桌面与窄屏可操作全部控件；三个图标不拆散、不被树抽屉或正文覆盖。
- [x] hover 与键盘焦点提示含义，键盘可打开排序入口并选择方向，亮/暗主题清晰。
- [x] 目录预览没有重复工具栏，类型显示与 Type 排序的分组含义一致。
- [x] 禁用 JS 后仍能改变列表隐藏与排序并完成目录/搜索导航；分别验证搜索的排序/隐藏操作、重新搜索及条目/../面包屑/搜索位置导航的必要参数，不丢失也不错误延续 q。
- [x] 文档正文、TOC、数学、Mermaid 与安全响应没有因工具区接入而改变渲染内容。
